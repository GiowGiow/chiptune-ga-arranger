# Contract: files that carry meters

## ABC input

Both readers accept these meter fields:

| Form | Example | Effect |
|---|---|---|
| header field | `M:3/4`, `M:C`, `M:C\|` | the meter of the first bar |
| inline field | `[M:2/4]` before a bar's first note | this bar and the following ones |
| body line | `M:6/8` on its own line | the next bar and the following ones |

Rules:
- `C` is 4/4 and `C|` is 2/2. The supported meters are listed in
  [../data-model.md](../data-model.md).
- An unsupported meter fails with `bar N: the meter 11/16 is not supported; supported meters:
  2/2, 2/4, 3/4, 4/4, 6/8, 9/8, 12/8, 5/4, 7/8`.
- A bar whose length differs from its meter fails, naming the bar and both lengths.
- A first bar that is shorter (a pickup) is refused by the command line and padded by the app.
- `L:` and `Q:` keep their meaning. `Q:3/8=120` is read in quarter notes, as 180.

## ABC output (writer)

- `M:` is the first bar's meter, in fraction form: `M:4/4`, never `M:C`.
- A bar whose meter differs from the previous bar starts with `[M:x]`.
- `L:1/16` as before. A bar holds `4 × bar_beats` units.
- A 4/4 lead sheet is written exactly as before this feature: the same text, byte for byte.

## Lead-sheet JSON (fixtures)

- Each bar gains `"meter": "3/4"`.
- The top-level `"beats_per_bar"` is gone.
- The JavaScript `leadSheetFromJson` reads a bar without `meter` as 4/4.

## Score-table JSON (fixtures)

- `act_no` is a list of n rows of 5 numbers instead of one list of 5.
- Every other field is unchanged.

## Fixture tree additions

`uv run src/main.py fixtures` writes, in addition to spec 002's files:

```text
arranger/tests/fixtures/
├── leadsheets/<meter tune>.json      # waltz, polka, jig, slow_twelve, five, seven, changes
├── realizations/<meter tune>.json    # every (bar, channel, gene value) realization
├── tables/<meter tune>.json
├── plans/meters-<meter tune>.json    # a fixed plan (gene b % size) with criterion scores, fitness, arrangement
├── abc/<meter tune>.abc              # the writer's text after a read (round trip)
└── midi-songs/
    ├── synthetic-waltz.mid / .json   # 3/4, melody + bass + pad tracks
    ├── synthetic-twelve-eight.mid / .json
    ├── synthetic-changes.mid / .json # 4/4 → 2/4 → 4/4
    └── synthetic-count-in.mid / .json  # drum-only 3/4 count-in, then 4/4
```

The source tunes are `tests/data/meters/<id>.abc`. They are written for this project and are
committed. The synthetic MIDI files are generated by `src/export/fixtures.py` and are committed
too, so that the JavaScript tests can read them without Python.

## MIDI output (arrangement)

- Track 0 holds the tempo and a time signature at beat 0 (the first bar's meter), plus one at
  each bar whose meter differs from the previous bar.
- An all-4/4 arrangement writes the same events as before: the samples' `piece.mid` and the app's
  Korobeiniki pin do not change.
- Time-signature events use the MIDI denominator form: 3/4 is written as numerator 3 and
  denominator 4. The metronome fields keep the values the library writes today.

## Run record (`config.json`)

- `allowed` is a new hyperparameter key; see [config.md](config.md).
- The input's meters are not written to the record. They come from the input.
